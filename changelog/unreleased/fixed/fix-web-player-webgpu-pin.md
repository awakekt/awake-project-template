The workflow now uses `<core>-SNAPSHOT`, the WebGPU snapshot of that release, and fails when that build or the web app's resolved classpath names any other Core. A scheduled run whose WebGPU build is not published yet waits for the next day instead; any other failed check still fails it. The release notes name the timestamped WebGPU build, and the template pins WebGPU `0.8.3-SNAPSHOT` for Core `0.8.3`.
